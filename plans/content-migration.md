# HTML 구현 및 문서 이전 기록

작성일: 2026-10-22. 사용자 요청에 따라 사이트를 HTML·CSS·JavaScript 방식으로 구현했다.

## 반영 범위

- 입력: 사용자가 제공한 `10.문서.zip`의 Markdown 26개와 PNG 5개
- 공개: 시작하기 3개, 기능 가이드 7개, 고급 기능 6개, 클래스 API 6개, CRUD 튜토리얼 1개
- 제외: `환경 구성 노트.md`, `_ BindModel 소스.md`, `ETC.md`의 내부 검토 내용
- 출력: 공개 문서 HTML 23개, 메인 화면, 404 페이지
- 원본→HTML 대응표: `migration-manifest.json`
- 기존 웹사이트는 정보 구조만 참고했으며 오래된 본문을 가져오지 않았다.

## 내용 정리

1. macOS 메타데이터와 Obsidian의 편집용 `%%` 주석을 공개 원고에서 제외했다.
2. 이미지 삽입 표기 6곳을 일반 이미지 참조로 바꾸고 이미지 5개를 포함했다.
3. U+0008 50곳과 추가 제어문자 6곳을 정리했다.
4. 클래스 이름 `BindCommnad`, `ProperyCollection`과 `ouputOption`, `vaild`를 정리했다.
5. `OutOptType.option`의 타입을 원고에 정의된 `OptionType`으로 맞췄다.
6. 기본 테이블을 변경하는 예제에서 `addTable('second', true)`를 사용하도록 정리했다.
7. 빠른 시작의 서비스 객체 매핑을 `cmd1: ['output']`으로 수정했다.
8. 빠른 시작의 브라우저 CDN을 검증 기준 버전 1.1.13으로 고정하고, Node CJS 배포 파일 확장자를 `.cjs`로 맞췄다.
9. 원본의 중복·불일치 다이어그램 중 컬럼 조회 설명에서 `getFilter` 단계가 빠진 도표를 제외했다. 최종 다이어그램은 8개다. 원본의 삭제 표시는 자동 실행 지시로 취급하지 않고 본문과 비교하여 편집했다.
10. JavaScript·TypeScript 코드의 잘못된 괄호·쉼표, `decalre`, `reutrn`, 타입 선언 문법, 서비스 클래스 문법 등을 정리했다. 독립 실행을 전제로 하지 않는 객체 속성 예시는 객체 리터럴 표현식으로 감쌌다.

모든 편집 처리는 `scripts/import-docs.mjs`에 남겼다. 현재 HTML은 직접 수정할 수 있으며, 재이전을 실행하면 해당 HTML은 다시 생성된다.

## 배포 패키지 확인

2026-10-22에 npm에서 `logic-bind-model@1.1.13`과 tarball을 확인했다. 로컬의 별도 개발 저장소와 npm 배포본의 구현이 다르므로, 실행 검증에는 npm tarball의 배포 파일을 사용했다.

- 일반 브라우저 배포본에서 모델 생성, 테이블 변경, 컬럼 값, 서비스 객체 매핑, selector와 getFilter의 조합을 확인했다.
- 메인 화면에서 실제 BindModel과 입력 요소를 연결하고, 사용자가 변경한 값이 모델을 통해 표시되는 것을 확인했다.
- npm 압축 배포본에서는 모델 생성 중 `EL01127 / EL04229` 오류를 재현했다. 사이트에는 실행을 확인한 일반 배포본을 포함했고, 빠른 시작의 압축본 안내 표는 제외했다.
- getFilter만 설정하고 selector 없이 값을 읽는 조합에서는 배포본 오류가 발생했다. 컬럼값 호출 구조와 HTMLColumn 문서에 selector 설정 안내를 추가했다. 사이트 구현은 해당 조합을 사용하지 않는다.
- 각 문서의 서버 요청 예제 전체를 실제 운영 서버와 연결해 실행한 것은 아니다. Node 설치·타입 선언의 완전한 호환성도 이번 사이트 검수 범위에 포함하지 않았다.

## 정적 파일 검사

- `npm run check`: HTML 25개의 내부 파일·자산·앵커, 제목·ID, 검색 대상과 자체 JavaScript 구문 검사 통과
- `npm run check:examples`: JavaScript·TypeScript 예제 556개의 구문 검사 통과
- 검색 자료: 문서 23개, 검색 섹션 414개
- 사이트맵: 공개 HTML 24개(404 제외)

예제 구문 검사 결과는 타입 검사나 비즈니스 동작 검증을 의미하지 않는다. 호출 순서와 출력 결과의 세부 사양은 추가 API 검토가 가능하도록 원문 내용을 유지했다.

## 운영 상태
